# ClickDoc Windows 版设计文档

日期：2026-10-28
状态：待用户审阅

## 1. 意图

ClickDoc 目前只有 macOS 版（v0.7.0，开源，官网 clickdoc.xiaohan.dev）。这次做一个功能相同的 Windows 版，让 Windows 用户也能"点一遍，教程自己写好"。

Windows 版是移植，不是新产品：用户在 Mac 版上能做的事，在 Windows 版上用同样的方式也能做，生成的教程内容也一样。Mac 版的代码和测试就是行为规格；本文档只写 Mac 版里看不出来的部分，以及 Windows 上需要不同处理的地方。

## 2. 目标

- 在 Windows 上实现和 Mac 版 v0.7.0 一样的完整流程：录制点击 → 自动截图并标出点击位置 → 编辑步骤（改文字、删除、排序、模糊、方框/箭头/文字标注）→ 导出 Markdown 文件夹、Notion 导入包或 PDF。
- 与 Mac 版同仓库、同版本号、同一个 GitHub Release 发布；官网按访客系统给出对应下载。
- 整个开发过程在作者的 Mac 上完成：写代码、编译、跑逻辑测试都在 Mac 上，GitHub Actions 出 Windows 安装包，在 Mac 上的 Windows 虚拟机里手动测试。

## 3. 非目标

- 不加 Mac 版没有的功能，也不砍 Mac 版已有的功能。
- 不支持 Windows 7、8、8.1。
- 不做代码签名、不上架 Microsoft Store / winget、不做 MSIX、不做自动更新。
- 第一版不出原生 ARM64 包（见 §7）。
- 不支持录制以管理员身份运行的程序（任务管理器、注册表编辑器等）。Windows 的权限隔离会让普通程序收不到这些窗口里的点击、读不到控件名。在安装说明里写明这一点即可。
- Windows 版和 Mac 版的草稿不需要互通。
- 不改动 Mac 版代码（`Sources/`、`scripts/` 等）。

## 4. 反目标（即使能跑也算失败）

沿用 Mac 版的反目标：

- 截图里看不清点了哪里，或者红圈位置偏了。在高 DPI（125%、150%、200% 缩放）、多显示器、各显示器缩放比例不同的情况下都必须准确。
- 点击 ClickDoc 自己的界面被记成步骤。在 Windows 上这还包括：托盘图标、托盘菜单，以及为了找到托盘图标而点开的任务栏溢出区（"^"箭头）。
- 录制时明显卡顿，影响被录软件的正常操作。
- 导出的 Markdown 在常见查看器里图片显示不出来。

Windows 版特有的：

- ClickDoc 自己的窗口（编辑器、托盘菜单）出现在截图里。Mac 版截图时会排除自身窗口，Windows 版必须一样。
- 截图发糊。程序必须按"每显示器 DPI 感知"运行，截到的是物理像素，不能被系统按 96 DPI 缩放后再放大。
- PDF 或图片标注里的中文显示成方块或空白。
- 鼠标钩子回调太慢，导致系统自动卸掉钩子，录到一半就不再记录点击。

## 5. 用户已确定的部分

### 5.1 技术路线

- C# + .NET 10 + WPF。注意：.NET 8 的支持期在 2026 年 11 月结束，所以不用 .NET 8。
- 代码放在仓库的 `windows/` 目录。
- 在 Mac 上开发和编译，用 GitHub Actions 出安装包，在 Mac 上的 Windows 虚拟机（UTM + Windows 11 ARM）里测试。
- 作者另有一台真实的 Windows 电脑，高 DPI 和多显示器相关的验证由作者本人在这台真机上完成。实现计划里要给出真机测试清单，供作者照着逐项测试。
- 安装包自带 .NET 运行时，用户不需要另外安装 .NET。安装包大约 70–100MB，用户可以接受。

### 5.2 系统要求

- 支持 Windows 10 和 Windows 11，不支持 Windows 7/8/8.1。具体最低小版本见 §7。

### 5.3 外观与入口

- 常驻在 Windows 任务栏右下角的托盘区，对应 Mac 版的菜单栏图标。托盘菜单的内容和 Mac 版菜单一致：
  1. 最近一次错误（有错误时才显示，用一行灰字）
  2. 开始录制 / 停止录制
  3. 截图范围：当前窗口 / 整个屏幕（单选，选择会记住）
  4. 打开编辑器
  5. 新建教程
  6. 退出
- 录制中，托盘图标要有明显区别，对应 Mac 版的实心录制图标。
- 界面中英双语，跟随 Windows 显示语言：显示语言为中文时用中文，其他语言一律用英文。生成的步骤描述、Markdown 和 PDF 也随之切换，规则同 Mac 版 `ContentLanguage`。

### 5.4 功能范围：与 Mac 版完全一致

以下行为以 Mac 版代码为准，Windows 版照做：

**录制**
- 左键单击记一步，右键单击记一步（描述用"右键点击"）。
- 双击合并为一步：把上一步的描述改成"双击"。三击及以上忽略。
- 点击 ClickDoc 自己的界面不记录。
- 录制期间编辑器窗口可以保持打开；"开始录制"会把新步骤接在当前教程末尾。
- 步骤描述的生成规则同 `describeStep`：
  - 中文：`在 <应用> 中点击「<控件名>」`
  - 英文：`Click "<控件名>" in <应用>`
  - 控件名超过 40 个字符时截断并加 `…`；拿不到应用名或控件名时，省略对应部分。
- 点击后立即截一张图，不在后台持续抓屏。截图里画上点击高亮：
  - 半透明红色实心圆（红色，透明度 0.3），加不透明的红色描边，线宽 4 个逻辑像素
  - 直径 60 个逻辑像素，按所在显示器的缩放比例换算成物理像素
  - 截图里包含鼠标指针（Mac 版 `showsCursor = true`）
  - 只保存画好高亮的图，不保留没有高亮的原图
- 截图范围：
  - "整个屏幕"：截点击所在的那块显示器。
  - "当前窗口"：按 Mac 版 `captureCropRect` 的规则裁剪：
    - 包含被点的窗口
    - 包含同一程序在附近弹出的菜单或弹层（距窗口 200 以内）
    - 给点击高亮留出余量（向外 32）
    - 四周再留 8 的边距，结果不超出显示器
    - 点在桌面或任务栏上，或者窗口几乎占满屏幕（面积超过显示器的 95%）时，退回整屏截图
    - 上面的数值都是逻辑像素

**编辑器**
- 左侧是步骤列表，每行显示：缩略图（80×48，已应用模糊和标注）、"步骤 n"、描述的第一行。
- 步骤列表的操作：
  - Ctrl 点选、Shift 连选、Ctrl+A 全选
  - 拖动调整顺序
  - 按 Delete 删除；右键菜单里有"删除"和"全选"
  - 一次删除多个步骤时先弹窗确认，删除后不能撤销
  - 删除后自动选中合适的下一步，规则同 `selectionAfterDeleting`
- 选中多个步骤时，右侧显示"已选择 n 个步骤"和一个批量删除按钮。
- 选中一个步骤时，右侧从上到下是：
  1. 工具栏：选择 / 模糊 / 方框 / 箭头 / 文字，"删除选中"，"清除全部"，以及当前工具的操作提示（把 Mac 提示里的 ⌘ 换成 Ctrl）
  2. 画布
  3. 描述编辑框
- 画布的交互同 `AnnotationEditing`：
  - 方框只在边框附近能点中，所以可以在方框内部画新的标注
  - 选中的方框或模糊区域可以拖右下角调整大小；选中的箭头可以分别拖两个端点
  - 标注和模糊区域可以拖动移动，但不会被拖出图片
  - 双击文字可以修改；文字工具下，在图上点一下就能输入，回车确认，Esc 取消
  - 按 Delete 删除选中的标注
- 标注的样式公式同 `AnnotationStyle`：
  - 线宽 `max(1.5, 图宽 × 0.0028)`
  - 字号 `max(10, 图宽 × 0.022)`，粗体
  - 文字为红色，外加白色描边
  - 红色值为 sRGB (0.93, 0.11, 0.14)
  - 箭头头部尺寸按线宽的倍数计算
- 模糊强度：高斯模糊，sigma = `max(图宽 / 150, 10)` 像素。原则是短文字一定看不清。
- 合成顺序：先模糊，再画标注。草稿里保存的是没模糊过的原图，加上模糊区域和标注的数据；导出时才把它们合成进图片。
- 窗口顶部有：教程标题输入框、开始/停止录制按钮、导出按钮。导出按钮是分体按钮：直接点主体导出 Markdown 文件夹，点旁边的箭头可以选 Markdown 文件夹 / Notion 导入包（.zip） / PDF。教程为空时禁用导出按钮。
- 编辑器窗口最小 760×480。

**导出**（所有格式都会把模糊和标注合成进图片）

- **Markdown 文件夹**：在用户选择的目录里，新建一个以教程标题命名的文件夹，里面是：
  - `tutorial.md`
  - `images/step-01.png`、`step-02.png` …，按最终顺序编号
  - Markdown 文本格式同 `renderMarkdown`
  - 文件夹名的清理和重名处理同 `sanitizeFolderName` 和 `uniqueFolderURL`。另外还要处理 Windows 文件名里不允许的字符（`<>:"/\|?*`）、保留名（CON、NUL 等），以及结尾的点和空格。
- **Notion 导入包**：生成 `<标题>.zip`，zip 根目录下是 `<标题>.md` 和 `images/`。
- **PDF**：
  - 页面：A4，页边距 50pt
  - 字体：标题 24pt 粗体，"步骤 n" 15pt 粗体，描述 12pt 深灰
  - 截图：缩放到内容区宽度，高度不超过 270pt；先缩到最长边 1600 像素以内，再用 JPEG 质量 0.8 嵌入
  - 同一步骤的标题、描述和截图不跨页拆开
- 导出前会提交正在输入的编辑内容。导出成功后，在资源管理器里打开并选中导出结果，并把"有未导出的修改"标记清掉。导出失败时弹窗显示原因。

**草稿**
- 当前教程自动保存（停止修改约 400ms 后写盘），退出时也会再存一次；重新启动后自动恢复。
- 草稿读不出来时，不覆盖它：把它挪到旁边一个带时间戳的目录里，并在托盘菜单的错误行里显示新位置。规则同 Mac 版 `restoreDraft`。
- "新建教程"会清空草稿；当前教程有未导出的修改时，先弹窗确认。

### 5.5 发布

- 和 Mac 版放在同一个 GitHub 仓库、同一个 Release 里，版本号统一读仓库根目录的 `VERSION` 文件。
- 安装包不签名。安装说明（中英文）要写清楚如何通过 SmartScreen 拦截：点"更多信息"，再点"仍要运行"。
- 官网的下载按钮根据访客的操作系统，自动给出 Mac 版或 Windows 版，同时提供另一个平台的下载链接。

## 6. 约束

- 开发机：Apple Silicon（arm64）Mac，macOS 15.7。目前还没装 .NET SDK，需要安装 .NET 10 SDK。没有 Xcode，但这对 Windows 版没有影响。
- 编译必须能在 Mac 上完成：WPF 项目要设置 `EnableWindowsTargeting=true`。
- Mac 上无法运行 WPF，所以凡是需要在 Mac 上测试的逻辑，都必须放在不依赖 WPF 的项目里（见 §7）。
- 依赖库的许可证必须与 MIT 兼容，而且不能收费。
- 提交代码时，作者身份必须用 `sean <1124832+ibeeger@users.noreply.github.com>`。
- 官网下载链接需要固定的文件名，所以每个 Release 都要同时提供带版本号的安装包，和一个固定文件名的安装包。

## 7. 我（Claude）替用户做的决定

以下是我的决定，用户没有专门讨论过，可以推翻。

- **最低版本是 Windows 10 2004（2020 年 5 月更新），不是任意版本的 Win10。** 原因：要让 ClickDoc 自己的窗口不出现在截图里，需要用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，这个能力从 2004 版才有。目前仍在用的 Win10 基本都是 22H2，影响很小。启动时如果检测到系统版本低于 2004，给出提示后退出。
- **项目结构：**
  - `windows/ClickDoc.Core`：目标框架 `net10.0`，不依赖 WPF。包含数据模型、点击判定、描述生成、控件命名、截图裁剪计算、画布命中测试、Markdown/zip 导出、草稿存取，以及所有图像处理（高亮、模糊、标注合成、缩略图、PDF）。
  - `windows/ClickDoc.Core.Tests`：xUnit 测试，在 Mac 上用 `dotnet test` 运行。可以参考 Mac 版 `Sources/CoreTests` 逐项移植。
  - `windows/ClickDoc`：目标框架 `net10.0-windows`，是 WPF 外壳。包含托盘、窗口、鼠标钩子、截屏、UI Automation、对话框。
  - 这样拆分是为了让大部分逻辑都能在 Mac 上测试，不必每次都进虚拟机。
- **图像处理和 PDF 用 SkiaSharp（MIT 许可）。** 它在 Mac 和 Windows 上都能运行，所以图像相关的测试也能在 Mac 上跑；还能直接生成 PDF 并嵌入字体，解决中文显示问题。代价是安装包会大约多出 10MB。
- **字体：**
  - Windows 上：标注和 PDF 用 Microsoft YaHei UI 的粗体（PDF 正文用常规体），在中英文环境下都一样。
  - Mac 上跑测试时：用系统里能找到的字体就行，测试不要依赖具体像素。
- **截图方式：** 用 GDI 截取整块显示器，自己画上鼠标指针，然后按需要裁剪。不用 Windows.Graphics.Capture，因为它在 Win10 上会给被截的窗口加一圈黄框，而且我们只需要静态截图。
- **"当前窗口"模式下怎么取窗口信息：**
  - 窗口的真实边框用 DWM 的 extended frame bounds 取，不用 `GetWindowRect`，因为后者会把 Win10/11 窗口外圈看不见的阴影边框也算进去。
  - 弹出菜单的判断依据是：和主窗口属于同一个进程的、可见的、无边框或带 `WS_POPUP` 样式的顶层窗口。
  - 系统菜单窗口（类名 `#32768`）也要识别为弹出菜单。
- **只装一个 x64 安装包，不出 ARM64 原生包。** x64 程序在 Windows 11 ARM 上可以靠模拟运行，作者在 UTM 虚拟机里测试的正是这种情况。以后需要时再加 ARM64 包。
- **安装包用 Inno Setup 制作：**
  - 按当前用户安装，不需要管理员权限，装到 `%LocalAppData%\Programs\ClickDoc`
  - 创建开始菜单快捷方式，带卸载程序
  - 安装界面有中英文
  - 覆盖安装即升级
  - 卸载时保留草稿
- **草稿位置改为 `%LocalAppData%\ClickDoc\draft`，不用之前说的 `%AppData%`。** 原因：`%AppData%` 在公司电脑上可能会随漫游配置文件同步，截图很占空间，不适合放那里。草稿的文件结构（`manifest.json` 加 `images/<id>.png`）沿用 Mac 版的思路，具体 JSON 格式由实现者决定。
- **启动行为：** 启动时直接打开编辑器窗口，这一点和 Mac 版不同（Mac 版启动后只出现菜单栏图标）。原因：Windows 11 默认会把新的托盘图标藏进溢出区，用户第一次启动很可能找不到它。编辑器在没有步骤时显示的提示语改为："还没有步骤。点上方的「开始录制」，或从任务栏右下角的托盘图标开始。"
- **托盘图标：** 左键和右键单击都弹出同一个菜单，和 Mac 版"点图标出菜单"的行为保持一致。
- **截图时机：** 在鼠标按下时立即截图，不等按键松开，也不额外延时。这和 Mac 版 v1 设计时用户的决定一致："点击后立即单次截图"，接受截图偶尔反映刚点完的状态。在"当前窗口"模式下，截完图后马上再查一次窗口；如果这次点击已经弹出了菜单，就把裁剪范围扩大到能包住菜单，做法同 Mac 版 `refine`。
  - 已知差异：Windows 的右键菜单是在按键**松开**时才弹出的，所以右键步骤的截图里通常看不到菜单。Mac 版的截图里常常能看到。这一点可以接受，因为下一步"点击菜单项"的截图里会有这个菜单。
- **界面风格：** 使用 .NET 10 WPF 自带的 Fluent 主题（`ThemeMode="System"`）。在 Win11 上看起来像原生应用，并且跟随系统的深色/浅色模式，对应 Mac 版跟随系统外观。画布上的选中手柄和高亮颜色在深浅两种模式下都要清楚可见。
- **只允许运行一个实例：** 第二次启动时，不再开一个新的 ClickDoc，而是把已经在运行的那个的编辑器窗口调到前台。
- **双击判定：** Windows 的底层鼠标钩子不提供"第几次点击"，所以要自己计算：
  - 两次左键按下的间隔不超过 `GetDoubleClickTime()`，位置差在 `SM_CXDOUBLECLK`/`SM_CYDOUBLECLK` 范围内，就累加点击次数；否则重新计为 1
  - 算出点击次数后交给 `decideStep`，判定规则同 Mac 版
  - "能不能把上一步升级成双击"的条件，也同 Mac 版的 `canUpgradeLastStep`
- **鼠标钩子回调只做两件事：** 记下按键、位置和时间，然后立即返回。查窗口、UI Automation、截图等工作都放到别的线程，按点击顺序依次处理，对应 Mac 版的串行处理链。截图要在点击后尽快开始，不能排在前面步骤的 UI Automation 查询后面等待。
- **控件名（UI Automation）：**
  - 用 `ElementFromPoint` 取到被点的控件。
  - Mac 的 `pickElementName` 对应到 Windows 是：
    - 标题 → `Name`
    - 帮助文字 → `HelpText`
    - Mac 的值字段只对静态文字使用；Windows 上 Text 控件的 `Name` 本身就是它的文字，所以这一项通常用不到
    - 实在没有名字时，最后退回 `LocalizedControlType`（控件类型名）
  - 父控件只取 `Name`。
  - 每次查询最多等 250ms，超时就当没拿到，不能阻塞后续处理。
- **应用名：** 优先用被点窗口所属进程的 exe 文件描述（`FileDescription`，比如 "Google Chrome"），取不到时用去掉 `.exe` 的进程名。
- **不把托盘相关点击记成步骤，具体做法：**
  - 点在 ClickDoc 托盘图标所在区域内的点击，忽略。图标区域用 `Shell_NotifyIconGetRect` 取得。
  - 点在 ClickDoc 自己窗口上的点击，忽略。判断方法：被点窗口所属的进程就是 ClickDoc 自己。
  - 通过托盘菜单停止录制时，如果最近 5 秒内的最后几步都是点在任务栏或托盘溢出区上的，就把这几步删掉。任务栏的窗口类是 `Shell_TrayWnd`，溢出区的窗口类是 `NotifyIconOverflowWindow` 或 Win11 上的对应窗口。
  - 实现者如果有更可靠的办法，可以替换，但 §4 的反目标必须满足。
- **界面文字和翻译：** 用 .resx 资源文件。中文原文和英文译文从 Mac 版的 `Localizable.strings` 搬过来，Windows 特有的文字另外补上。测试要检查：每一条中文都有对应的英文。
- **应用图标：** 从根目录的 `icon.png` 生成包含多种尺寸的 `.ico`（16 到 256），并提交进仓库。生成方式由实现者决定。
- **CI 和发布流程：**
  - 新增 `.github/workflows/windows.yml`，在 `windows-latest` 上运行。
  - 触发条件和对应动作：

    | 触发 | 动作 |
    |---|---|
    | `windows/**` 有改动的 push 或 PR | 编译 + 测试 |
    | 手动触发 | 编译、测试，并打出安装包，作为 Actions 产物上传 |
    | GitHub Release 发布（published） | 编译、测试、打包，并把安装包上传到这个 Release |

  - 这样作者原来的发布流程不用变：在 Mac 上运行 `release.sh`，手动建 Release、上传 dmg；Release 发布后，Windows 安装包会自动挂上去。
  - Release 里的 Windows 文件：`ClickDoc-<版本>-Setup.exe`，以及固定文件名的 `ClickDoc-Setup.exe`，官网链接指向后者。
  - 工作流要先检查 Release 的标签和 `VERSION` 文件是否一致，不一致就报错停止。
  - 移植完成之前，"Release 发布时打包上传"这一步保持关闭。这样移植中途发布的 Mac 版本，不会被挂上一个半成品的 Windows 安装包。移植完成后，第一个同时包含 Windows 版的版本定为 0.8.0。
  - Release 发布后，Windows 安装包要等几分钟才能编译好挂上去。这几分钟里官网的 Windows 下载链接会是 404，这个可以接受。如果编译失败，GitHub 会发邮件通知作者，由作者手动修复，不另做备用链接。
- **官网改动的上线时机：** 等 0.8.0 的 Release 上已经确实挂好了 `ClickDoc-Setup.exe`，再合并官网改动。
- **官网改动：**
  - 用 `navigator.userAgentData.platform`（取不到时用 userAgent）判断访客的系统。主按钮显示"下载 Windows 版"或"下载 macOS 版"，下面附一行另一平台的下载链接。无法判断系统时，默认显示 macOS 版。
  - 安装步骤部分分成 Mac 和 Windows 两块。
  - 中英文文案都要更新。
- **README 和打包文件：**
  - README 增加 Windows 的安装和开发说明。
  - `packaging/` 下新增 Windows 版的中英文安装说明，内容包括：如何通过 SmartScreen、托盘图标在哪里、不能录制管理员程序。

## 8. 留给实现者决定

- 托盘的实现方式：用 WinForms 的 `NotifyIcon`，还是 H.NotifyIcon 之类的 MIT 许可库。
- 画布的绘制方式：比如用 SkiaSharp 渲染合成结果再显示，选中手柄用 WPF 叠加；或者其他做法。要求是画布上看到的效果和导出结果一致，文字框大小要和导出时一致。
- 截图的执行时机和排队方式，只要录制时不卡顿、截图反映的是这次点击时的画面就行。
- 草稿 JSON 的具体格式。
- 文件夹选择对话框用哪个 API（.NET 8 起 WPF 自带 `OpenFolderDialog`）。
- 代码模块的划分和文件结构（§7 的三个项目这一层以下）。
- 在 Mac 上安装 .NET 10 SDK 的方式（Homebrew 或官方 pkg）。
- 手动测试清单：放在实现计划里。至少要覆盖：100%/150%/200% 缩放、两块缩放比例不同的显示器、右键菜单和下拉菜单的截图范围、托盘溢出区、单实例、升级安装后草稿保留。
