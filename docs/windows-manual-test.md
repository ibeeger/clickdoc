# ClickDoc Windows 版手动测试清单

自动测试（`dotnet test windows/ClickDoc.Core.Tests`）覆盖了逻辑和图像处理：点击判定、裁剪计算、模糊和标注渲染、导出格式、草稿读写。凡是要真的跑在 Windows 上才能验证的部分，都在这份清单里，每项写明了操作和预期结果。

## 测试用的程序从哪来

有两种获取方式，任选其一：

- **从 Mac 拷过去：** 在 Mac 上运行 `windows/scripts/publish.sh`，把生成的 `windows/out/ClickDoc` 文件夹拷进 Windows，直接运行里面的 `ClickDoc.exe`。这种方式不需要安装。
- **下载安装包：** 在 GitHub Actions 里手动运行一次 “Windows” 工作流，下载产物 `ClickDoc-Windows`，然后运行 `ClickDoc-Setup.exe` 安装。

清单分两部分：**A 部分**在任何 Windows 上都能测，虚拟机也可以；**B 部分**必须用真机。

## A. 基本功能（虚拟机或真机）

### A1. 启动与托盘

| # | 操作 | 预期 |
|---|---|---|
| 1 | 第一次启动 | 编辑窗口自动打开，显示“还没有步骤……”；任务栏托盘区出现 ClickDoc 图标（可能在 “^” 里） |
| 2 | 分别用左键、右键点托盘图标 | 都弹出同一个菜单：开始录制 / 截图范围 / 打开编辑器 / 新建教程 / 退出 |
| 3 | 菜单打开后，点菜单外的桌面 | 菜单关闭 |
| 4 | 关掉编辑窗口，再从托盘点“打开编辑器” | 编辑窗口重新出现，程序没有退出 |
| 5 | ClickDoc 运行时，再双击一次 exe | 不会出现第二个 ClickDoc，已打开的编辑窗口被调到最前 |
| 6 | 把 Windows 显示语言切换为英文，重启 ClickDoc | 界面和新录制的步骤描述都是英文 |
| 7 | 在系统设置里切换到深色模式 | 编辑窗口跟着变深色，文字清晰可读 |
| 8 | 资源管理器重启后（任务管理器 → 重启“Windows 资源管理器”） | 托盘图标自动重新出现 |

### A2. 录制

| # | 操作 | 预期 |
|---|---|---|
| 1 | 开始录制，在记事本里单击菜单“文件” | 新增一步，描述类似“在 记事本 中点击「文件」”，截图上有红圈 |
| 2 | 双击记事本标题栏 | 只生成一步，描述为“双击” |
| 3 | 在记事本正文里右键 | 新增一步，描述为“右键点击” |
| 4 | 在正文里快速三击 | 前两下合并成一步“双击”，第三下不生成新步骤 |
| 5 | 录制中点编辑窗口里的任何地方 | 不生成步骤 |
| 6 | 录制中其他步骤的截图里 | 看不到 ClickDoc 的编辑窗口（即使它就挡在被点的窗口上面） |
| 7 | 托盘图标在 “^” 溢出区里时：点 “^” → 点 ClickDoc 图标 → 停止录制 | 点 “^” 和点托盘图标这两下都不留在步骤里 |
| 8 | 截图范围选“当前窗口”，点记事本的“文件”菜单 | 截图只包含记事本窗口，以及弹出的菜单 |
| 9 | 截图范围选“当前窗口”，点桌面 | 截整个屏幕 |
| 10 | 截图范围选“整个屏幕”，点任意位置 | 截整个屏幕 |
| 11 | 打开“设置”或“计算器”，点其中的按钮 | 描述里的应用名是“设置”或“计算器”，不是 “Application Frame Host” |
| 12 | 在一个窗口里连续快速点 10 次不同位置 | 生成 10 步，顺序和点击顺序一致 |
| 13 | 截图范围设为“整个屏幕”后退出再启动 | 托盘菜单里仍然勾选“整个屏幕” |

### A3. 编辑器

| # | 操作 | 预期 |
|---|---|---|
| 1 | 列表中按 Ctrl 点选、Shift 连选、Ctrl+A 全选 | 都能多选；右侧显示“已选择 n 个步骤” |
| 2 | 多选后按 Delete | 先弹出确认框；确认后删除，并自动选中原位置的下一步 |
| 3 | 只选一步时按 Delete | 不弹确认框，直接删除 |
| 4 | 在某一步上右键 | 菜单里有“删除”（多选时显示“删除所选的 n 个步骤”）和“全选” |
| 5 | 拖动一步到别的位置 | 拖动时显示插入线；松开后顺序改变，“步骤 n”的编号随之更新 |
| 6 | 修改描述 | 左侧列表那一行的文字同步更新 |
| 7 | 修改标题和描述后退出，再重新打开 | 修改都还在 |

### A4. 标注

| # | 操作 | 预期 |
|---|---|---|
| 1 | 用模糊、方框、箭头工具分别画一个 | 都能画出来；画得太小会被忽略 |
| 2 | 用选择工具点选、拖动、拖右下角或箭头端点 | 能选中、移动、调整大小；不会被拖出图片 |
| 3 | 在方框内部按下拖动 | 画出新的标注，而不是移动外面的方框 |
| 4 | 文字工具：点一下 → 输入 → 回车 | 文字出现；按 Esc 取消，什么都不留下 |
| 5 | 双击已有的文字 | 进入修改；内容清空后回车，这条文字被删除 |
| 6 | 选中某个标注后按 Delete，或点“删除选中” | 被删除 |
| 7 | 点“清除全部” | 这一步的模糊和标注全部清空 |
| 8 | 标注改动后看左侧列表 | 缩略图同步更新 |
| 9 | 切换到深色模式 | 选中手柄和模糊区域的虚线框仍然看得清 |

### A5. 导出与新建

| # | 操作 | 预期 |
|---|---|---|
| 1 | 直接点“导出”按钮主体 | 选文件夹后生成 Markdown 文件夹，并在资源管理器中选中它；用 VS Code 预览能看到图片 |
| 2 | 点“导出”右侧箭头 → Notion 导入包 | 生成 zip；在 Notion 里“导入 → Markdown”后图片正常显示 |
| 3 | 点“导出”右侧箭头 → PDF | 用 Edge 打开：中文正常、每步的标题文字和截图不跨页拆开、模糊和标注都画进了图里 |
| 4 | 标题改为 `CON` 后导出 | 导出成功，文件夹名为 `CON_` |
| 5 | 在描述框里输入时（或正在输入文字标注时）直接点导出 | 刚输入的内容也被导出 |
| 6 | 有未导出的修改时点“新建教程” | 先弹确认框；确认后清空 |
| 7 | 导出到没有写权限的目录（如 `C:\Windows`） | 弹出“导出失败”和原因，程序不崩溃 |

## B. 真机测试（作者执行）

### B1. 缩放比例

分别把显示缩放设为 **100%、125%、150%、200%**，每种比例下各录一次：

- [ ] 红圈正好落在点击位置，大小看起来一致（约 60 个逻辑像素）
- [ ] 截图清晰不发糊，分辨率与屏幕的物理像素一致
- [ ] “当前窗口”模式的裁剪紧贴窗口，四周不多出一圈阴影边框

### B2. 多显示器

接两块显示器，把它们的缩放比例设成不一样（例如主屏 100%、副屏 150%）：

- [ ] 副屏放在主屏左边时，在副屏上录制：红圈位置和裁剪都正确
- [ ] 副屏放在主屏上方时，同样正确
- [ ] 把编辑窗口在两块屏之间拖来拖去，界面清晰，画布上的标注和手柄位置正确
- [ ] 截图只截被点的那块屏

### B3. 菜单与弹窗

- [ ] 在 Chrome 或 Edge 里右键：截图范围包含网页窗口（菜单是松开按键时才弹出的，所以这一步截图里看不到菜单）
- [ ] 下一步点菜单项时：截图里包含这个右键菜单
- [ ] 点 Office 或资源管理器的下拉菜单：截图里包含下拉菜单
- [ ] VS Code 这类无边框窗口：“当前窗口”模式能正常裁剪到窗口，而不是总截整屏

### B4. 安装、升级与卸载

- [ ] 下载 `ClickDoc-Setup.exe` 后运行，SmartScreen 拦截时点“更多信息” → “仍要运行”能继续安装
- [ ] 安装过程中不要求管理员权限
- [ ] 开始菜单里有 ClickDoc
- [ ] 先录几步不导出，再运行新版安装包覆盖安装：草稿还在
- [ ] ClickDoc 运行时运行安装包：安装程序提示先关闭 ClickDoc
- [ ] 卸载后 `%LocalAppData%\ClickDoc\draft` 还在

### B5. 特殊情况

- [ ] 以管理员身份打开任务管理器，在里面点击：不生成步骤，ClickDoc 不崩溃
- [ ] 点一个卡住（未响应）的程序：仍然生成步骤（只是没有控件名），之后的点击不受拖累
- [ ] 在 Windows 11 ARM 虚拟机上（x64 程序在模拟下运行）：录制和导出都正常
